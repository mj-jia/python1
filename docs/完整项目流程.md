## 1. 退化流水线（创新一）

**文件**：`src/degrade/dct_degrade.py`

链路顺序为：

```
整数倍下采样 → 非均匀 DCT 编码 → 二次转码 → 插值放大
```

为什么这个顺序：真实传图是"先缩到 1080 档，再编码上传，最后显示端放大"。
顺序写反（先编码再缩放）会让降分辨率把编码阶段的差异全部抹平。

**关键实现**：

| 环节 | 做法 | 为什么不能用现成库 |
|---|---|---|
| 量化步长 | 逐块计算，`q = f(局部纹理能量)` | libjpeg 的 quality 是图像级参数，DQT 表全局唯一 |
| DCT | 纯 numpy，8×8 正交矩阵 | 需要拿到每块系数做量化 |
| 色度 | 4:2:0 + 统一低质量 | 复现色带 |
| 缩放 | **整数倍**（默认 2） | 非整数倍会让放大后的块间距不是整数，块效应无法度量 |

方向必须写对：**E 大（纹理）→ quality 高 → 量化步长小**；E 小（平坦）→ quality 低 → 步长大。

**验收**：

```bash
python tools/verify_nonuniform.py
```

产物：`experiments/verify/report.md` + 三张图（quality 热力图、三联对比、平坦/纹理局部放大）。

报告里应能读到：
- 逐块 quality 与局部能量的相关系数 r ≈ 0.96（强正相关）
- 平坦区块效应 > 纹理区块效应（内容依赖生效）
- 均匀分配时这个比值被拉平

## 2. 损失函数（创新二、三）

**文件**：`src/train/losses.py`

### 2.1 BlockinessLoss（创新二）

```
blockiness(x) = 块边界梯度均值 / (块内梯度均值 + 0.5/255)
L_block = relu(blockiness(pred) - blockiness(gt)) / clamp(blockiness(gt), 0.3)
```

- `relu` 单向惩罚：只在"输出比 GT 更像块状"时罚，不误伤正常边缘。
- 除以 GT 的块效应水平：做成无量纲量，便于与 L1 配权重。
- **block 参数 = 8 × 下采样倍数**（默认 16），因为退化图上的块被放大了。

### 2.2 SpatialAdaptiveLoss（创新三）

```
w = τ / (局部梯度能量 + τ)          # 1=平坦，0=纹理
L = mean(w ⊙ L1)/s1 + mean((1-w) ⊙ LPIPS_spatial)/s2
```

四个坑（都已在代码里规避）：

1. LPIPS 必须 `spatial=True`，否则只有全局标量；
2. 这是**空间**加权，不是训练中自适应调权重系数（后者是 uncertainty weighting）；
3. L1 与 LPIPS 尺度不同，加权前必须归一化（`s1`、`s2` 由 detach 后的均值给出）；
4. 平坦区不要纯 L1（L1 最优解偏中值，加重平滑感），由外部再叠加块效应项。

## 3. 模型

**文件**：`src/models/srvgg.py`

Real-ESRGAN 的 `SRVGGNetCompact`，`num_feat=64, num_conv=32, upscale=1`，
参数量 ≈1.15M，与官方 `realesr-general-x4v3` 同级。**结构不做任何改动**。

两个必要的工程细节：

- 残差学习：`out = body(x) + x`；
- 最后一层权重初始化为 0，保证训练起点是恒等映射（否则一上来就把图弄坏）。

## 4. 训练（四组消融）

**文件**：`src/train/train_sr.py`

| 组 | 退化建模 | 块效应损失 | 空间加权 | 回答什么 |
|---|---|---|---|---|
| A | 非均匀 | ✗ | ✗ | 只用退化建模的收益 |
| B | 非均匀 | ✓ | ✗ | 创新二单独贡献 |
| C | 非均匀 | ✗ | ✓ | 创新三单独贡献 |
| D | 非均匀 | ✓ | ✓ | 合起来多少 |
| U（附加） | **均匀** | ✓ | ✓ | 退化建模本身有没有用 |

```bash
# 单组
python src/train/train_sr.py --exp D --iters 6000

# 四组串行
bash scripts/run_ablation.sh 6000
```

同 seed、同迭代、同数据量、同验证集，唯一变量是开关。

训练配置：patch 256、batch 16、Adam 2e-4、cosine + 500 iter warmup、AMP。
迭代数按机器定，6000 iter 在 A10 上约 35 min/组。

**验收**：
- `experiments/exp_*/train_log.jsonl` 里 loss 单调下降（允许抖动）；
- `[val]` 行的 PSNR 逐次上升；
- `experiments/exp_*/best.pth` 存在。

## 5. 评测

**文件**：`src/eval/benchmark.py`

```bash
python src/eval/benchmark.py --ckpt experiments/exp_A/best.pth --tag A
python src/eval/benchmark.py --tag degraded          # 退化图基线
```

口径：test 80 张、512 center crop、退化 seed 固定（所有方法看到相同输入）。

指标：
- 全局：PSNR / SSIM / LPIPS / 块效应
- 分区：平坦区 Δ块效应、纹理区 Δ块效应、纹理区梯度能量保留率、分区 PSNR

**分区指标是说服力的来源**：整体 PSNR 通常只涨 0.3~0.8 dB，单看它说明不了问题。

## 8. 答辩五问的对应证据

1. **"主干是开源的，你做了什么"**
   → 退化定义、损失目标、分区权衡三处改造；第 1、2 节的代码与消融。

2. **"PSNR 只涨 0.5 dB 有意义吗"**
   → 换分区指标：平坦区块效应下降多少 + 局部放大图。

3. **"仿真凭什么代表真实传输"**
   → 需要 20 对真实微信传输图做验证集，报告里单列一行。**这一项尚未做**，
      当前退化参数（2 倍下采样、q42~78、二次转码 q58~72）是按公开资料设定的，
      必须用真实样本校准后才能写进结论。

4. **"为什么不直接把模型做大"**
   → 端侧复原是场景前提，服务端复原要多传一次，带宽反而更贵。

5. **"创新一是不是只是造数据"**
   → 退化被参数化后可做开关消融（U 组就是"关掉非均匀"的对照）。

## 9. 已知限制（写进"局限"一节）

- 块级量化步长是对真实编码器 AQ（自适应量化）的近似。baseline JPEG 的
  DQT 表是全局的，逐块步长并非 JPEG 标准行为；对现代编码器（HEVC/AV1 的 AQ）
  才是准确建模。文档中应表述为"近似 AQ 行为"，不要声称逐比特复刻。
- 缩放固定为整数倍以换取块网格可度量，与真实 1.89 倍（2040→1080）有偏差。
- 未使用真实传输样本校准退化参数。
